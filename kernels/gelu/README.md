# Gelu

## 0x00 说明

本模块是 LeetCUDA `kernels/gelu` 的 Intel oneAPI/SYCL 移植版本，包含：

- [X] `gelu_f32`：FP32 标量版（SYCL，每 work-item 1 个元素）
- [X] `gelu_f32x4`：FP32 向量化版（`sycl::vec<float,4>`，16 字节访存）
- [X] `gelu_f16`：FP16 标量版（`sycl::half`）
- [X] `gelu_f16x2`：FP16 每 work-item 2 元素（4 字节访存）
- [X] `gelu_f16x8`：FP16 每 work-item 8 元素（4 次 4 字节访存，unpack）
- [X] `gelu_f16x8_pack`：FP16 每 work-item 8 元素（128 位打包访存）
- [X] PyTorch XPU bindings

计算公式（默认走 tanh 近似，与 CUDA 版一致）：

```text
gelu(x) ≈ 0.5 * x * (1 + tanh(sqrt(2/pi) * (x + 0.044715 * x^3)))
```

代码文件：

| 文件 | 作用 |
| --- | --- |
| `gelu.sycl` | SYCL kernel + PyTorch XPU 绑定（对应 CUDA 版 `gelu.cu`） |
| `gelu.py` | 用 `torch.utils.cpp_extension.load` 编译 `.sycl` 并执行基准测试 |

> 说明：本模块严格照搬 CUDA 版的算法与启动配置，**包括**已知缺陷——
> FP16 版本在 `x ≳ 4.03` 时输出 NaN（clamp 夹的是输入 `x`，而送进 `exp` 的是
> 含 `x³` 的 `2*inner`）、FP32 版本对大输入截断且吞掉 NaN、向量化版本
> `f32x4` / `f16x2` / `f16x8` 还会越界读（详见 `../../docs/kernels/gelu/README.md`）。
> 基准测试的 `S`、`K` 都是 256 的倍数，不会触发越界问题。

## 测试

先按 `../../scripts/README.md` 完成环境搭建（Intel oneAPI 容器 + Python venv +
PyTorch XPU），然后运行：

```bash
# 进入 oneAPI 容器后手动执行（命令详见 ../../scripts/README.md）
sudo docker start leetoneapi
sudo docker exec -it leetoneapi /bin/bash

cd /workspace/LeetOneAPI
source .venv/bin/activate
cd /workspace/LeetOneAPI/kernels/gelu
python3 gelu.py
```

默认 `gelu.py` 使用 JIT（仅 spir64）编译；需要 AOT 时自行设置
`TORCH_XPU_ARCH_LIST`（见 `../../scripts/README.md`）。

判断标准：

- 同一次运行的 FP32 三个输出前 2 个元素应一致（`f32` / `f32x4` / `torch GELU("tanh")`）；
- FP16 各版本彼此一致，但与 PyTorch 的差异**大于** relu / elu / swish 等模块——
  因为 tanh 是用 `exp` 拼出来的，存在相减抵消（PyTorch 内部把 half 提升到 float 再算）；
- **上面的输出只抽查了前 2 个元素**，看不出 NaN；大尺寸的 FP16 组里混有
  `|x| > 4.03` 的元素，它们会被算成 NaN。要确认可以单独跑边界用例（见下）。

### 边界行为实测

```text
gelu_f16 [3.9, 4.0, 4.03, 4.1] = [3.900390625, 3.998046875, nan, nan]
gelu_f32 [100, -100, nan, 4]   = [88.37625885009766, -0.0, -0.0, 3.999929904937744]
torch GELU("tanh") 同一输入    = [100.0, -0.0, nan, 3.999929904937744]
```

三行对照说明：

1. FP16 在 `x = 4.0` 还正常、`x = 4.03` 已经变成 NaN——这就是
   “clamp 夹了 `x` 而不是 `inner`”导致的问题；
2. FP32 把 100 截断成 88.376，把 NaN 吞成 -0.0，而 PyTorch 分别是 100 和 NaN；
3. 只有 `x = 4` 这种常规输入下两者才一致（`3.999929904937744`）。

## CUDA → SYCL 速查

| CUDA | oneAPI / SYCL |
| --- | --- |
| `gelu.cu` + nvcc | `gelu.sycl` + `icpx -fsycl` |
| `kernel<<<grid, block>>>(args)` | `queue.submit` + `parallel_for(nd_range)` |
| `blockIdx.x * blockDim.x + threadIdx.x` | `item.get_global_id(0)` |
| `float4` / `half2` | `sycl::vec<float,4>` / `sycl::vec<sycl::half,2>` |
| `tanhf`（FP32） | `sycl::tanh`（FP32） |
| `hexp` 拼 tanh（FP16） | `sycl::exp` 拼 tanh（FP16） |
| `erff`（精确式） | `sycl::erf` |
| `fminf` / `fmaxf` / `__hmin` / `__hmax` | `sycl::fmin` / `sycl::fmax` |
| `__float2half(1.0f)` | `sycl::half(1.0f)` |
| `torch.cuda` / `.cuda()` | `torch.xpu` / `.xpu()` |
| `TORCH_CUDA_ARCH_LIST` | `TORCH_XPU_ARCH_LIST` |

> SYCL 侧的一个额外注意点：`M_SQRT2` / `M_2_SQRTPI` 是 double 类型常量，
> 若照抄 CUDA 的 `#define SQRT_2_PI (M_SQRT2 * M_2_SQRTPI * 0.5f)`，
> 整个表达式是 double，`sycl::tanh` 会解析到 double 重载，
> 在 Intel GPU 上直接报 `Required aspect fp64 is not supported`。
> 本模块把系数显式转成 float（`static_cast<float>(M_SQRT2) * ...`）规避该问题。

详细设计说明见 `../../docs/kernels/gelu/README.md`。
