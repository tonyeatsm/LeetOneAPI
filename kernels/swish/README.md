# Swish

## 0x00 说明

本模块是 LeetCUDA `kernels/swish` 的 Intel oneAPI/SYCL 移植版本，包含：

- [X] `swish_f32`：FP32 标量版（SYCL，每 work-item 1 个元素）
- [X] `swish_f32x4`：FP32 向量化版（`sycl::vec<float,4>`，16 字节访存）
- [X] `swish_f16`：FP16 标量版（`sycl::half`）
- [X] `swish_f16x2`：FP16 每 work-item 2 元素（4 字节访存）
- [X] `swish_f16x8`：FP16 每 work-item 8 元素（4 次 4 字节访存，unpack）
- [X] `swish_f16x8_pack`：FP16 每 work-item 8 元素（128 位打包访存）
- [X] PyTorch XPU bindings

计算公式：`y[i] = x / (1 + exp(-x))`，等价于 `x * sigmoid(x)`。
命名上 swish 与 silu 是同一个函数（PyTorch 叫 SiLU），本模块沿用仓库里的 `swish`。

代码文件：

| 文件 | 作用 |
| --- | --- |
| `swish.sycl` | SYCL kernel + PyTorch XPU 绑定（对应 CUDA 版 `swish.cu`） |
| `swish.py` | 用 `torch.utils.cpp_extension.load` 编译 `.sycl` 并执行基准测试 |

> 说明：本模块严格照搬 CUDA 版的算法与启动配置，**包括**已知缺陷——
> FP16 在 `x <= -11.09` 时饱和成 `-0.0`、FP32 极小负数下溢成 `-0.0`，
> 以及 `f32x4` / `f16x2` / `f16x8` 缺少 tail 分支（`N` 不是向量宽度整数倍时
> 会越界写）、`f16x8_pack` 尾部整段漏算。基准测试的 `S`、`K` 都是 256 的倍数，
> 不会触发这些问题。详见 `../../docs/kernels/swish/README.md`。

## 测试

先按 `../../scripts/README.md` 完成环境搭建（Intel oneAPI 容器 + Python venv +
PyTorch XPU），然后运行：

```bash
# 进入 oneAPI 容器后手动执行（命令详见 ../../scripts/README.md）
sudo docker start leetoneapi
sudo docker exec -it leetoneapi /bin/bash

cd /workspace/LeetOneAPI
source .venv/bin/activate
cd /workspace/LeetOneAPI/kernels/swish
python3 swish.py
```

默认 `swish.py` 使用 JIT（仅 spir64）编译；需要 AOT 时自行设置
`TORCH_XPU_ARCH_LIST`（见 `../../scripts/README.md`）。

判断标准：

- 同一次运行的 FP32 三个输出前 2 个元素应一致（`f32` / `f32x4` / `torch_swish`）；
- 同一次运行的 FP16 各版本输出前 2 个元素应一致；
- FP16 与 FP32 允许有约 `1/1024` 量级的量化差异；
- 负半轴输出是小负数（不是硬零），没有出现 `NaN` / `inf`——
  这正是“`exp` 放在分母上安全”的直接体现（对照 gelu 会 NaN）；
- 对照实现 `torch_swish` 是 `sigmoid + mul_` 两个 kernel，`out_*_th` 偏慢属正常。

### 边界行为实测

```text
swish_f16 [-11, -11.09, -12, -9] = [-0.0001835823, -0.0, -0.0, -0.0011100769]
torch silu(float32 of 同输入)    = [-0.0001837156, -0.0001687009, -7.373010e-05, -0.0011105513]
```

`x = -11` 时两者还一致（约 `-1.8e-4`），从 `x = -11.09` 起 kernel 因为
`exp(-x)` 溢出成 `inf` 而得到 `x * 0 = -0.0`，PyTorch 仍给出 `-1.69e-4`
（`x = -12` 时是 `-7.37e-5`）——绝对误差在 `1e-4` 量级，但**符号不同**。

## CUDA → SYCL 速查

| CUDA | oneAPI / SYCL |
| --- | --- |
| `swish.cu` + nvcc | `swish.sycl` + `icpx -fsycl` |
| `kernel<<<grid, block>>>(args)` | `queue.submit` + `parallel_for(nd_range)` |
| `blockIdx.x * blockDim.x + threadIdx.x` | `item.get_global_id(0)` |
| `float4` / `half2` | `sycl::vec<float,4>` / `sycl::vec<sycl::half,2>` |
| `x / (1.0f + expf(-x))`（FP32） | `x / (1.0f + sycl::exp(-x))` |
| `__hmul(x, __hdiv(1, 1 + hexp(-x)))`（FP16） | `x * (sycl::half(1.0f) / (sycl::half(1.0f) + sycl::exp(-x)))` |
| `__float2half(1.0f)` | `sycl::half(1.0f)` |
| `torch.cuda` / `.cuda()` | `torch.xpu` / `.xpu()` |
| `TORCH_CUDA_ARCH_LIST` | `TORCH_XPU_ARCH_LIST` |

详细设计说明见 `../../docs/kernels/swish/README.md`。
